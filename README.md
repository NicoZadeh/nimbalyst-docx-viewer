# DOCX Viewer

A Nimbalyst extension that renders Word `.docx` documents inline, read-only, and exposes their text to the assistant.

## What it does (v1)

- Faithful read-only rendering of `.docx` files via [docx-preview](https://github.com/VolodymyrBaydalka/docxjs).
- Continuous vertical scroll through the whole document.
- Zoom in, zoom out, and reset zoom.
- Fit-to-width.
- Keyboard shortcuts: Cmd/Ctrl `+` to zoom in, Cmd/Ctrl `-` to zoom out, Cmd/Ctrl `0` to reset.
- Safe hyperlink handling.
- One AI tool, `docx.get_text`, that returns the document's plain text to the assistant.

Comments and tracked changes are intentionally NOT rendered. Editing and saving, document outline, metadata, and section navigation are out of scope for v1.

## Security

- docx-preview runs with hardened options. `renderAltChunks`, `renderComments`, and `renderChanges` are all off, so external chunks, comment threads, and tracked-change markup never reach the DOM.
- Links are neutralized before they are clickable. `javascript:`, `data:`, `vbscript:`, and `file:` URLs are blocked. `http(s)` links are routed through `window.electronAPI.openExternal` rather than navigating the renderer.
- Mammoth is used only through `extractRawText`. There is no HTML conversion, no image extraction, and no external resource surface.

## Size & timeout policy

- Soft limit is roughly 25 MB. The hard limit is 50 MB for rendering and 25 MB for text extraction.
- The `byteLength` guard is the real safeguard. It runs before Mammoth is invoked, so an oversized payload is rejected up front.
- The extraction timeout, roughly 20 seconds, is BEST EFFORT only. Mammoth parses on the main thread, so a CPU-bound parse blocks the timer and the timeout cannot fire mid-parse.
- The initial host binary load cannot be preflighted. There is no host stat API, so very large hidden documents remain best effort.

## Install locally in Nimbalyst (dev)

Requires Nimbalyst app >= 0.58.5.

1. `npm ci`
2. `npm run build`
3. Install the local folder via Extension Dev Tools (the `extension_install` flow).
4. Iterate with `extension_build`, `extension_install`, and `extension_reload`.

## Manual test checklist

1. Open `samples/demo.docx`. Confirm it renders, that zoom and fit-width work, and that Cmd/Ctrl `+`/`-`/`0` work.
2. Ask the assistant to summarize a `.docx` that is NOT open in a visible tab. Confirm the host mounts a hidden editor, that `registerEditorAPI` fires within roughly 10 seconds, and that `docx.get_text` returns text.
3. Security smoke with `samples/demo-links.docx`. The `https` link opens via `openExternal`, the `javascript:` link is neutralized (struck through, not clickable), and the comment and tracked change are NOT rendered.
4. Size policy. A large doc shows the loading copy. An oversized one shows the hard-limit message and `docx.get_text` fails fast.
5. Large-image memory with `samples/demo-images.docx`. Open it and note renderer memory with `useBase64URL: true`.

## Build & test

- `npm run build`
- `npm test`
- `npm run typecheck`
- `npm run package` (needs the `zip` CLI)

The `samples/` documents are generated by `python3 scripts/make-fixtures.py` (PIL required).

## Deviations from the plan

- Packaging uses the system `zip` CLI rather than an npm zip dependency.
- `extractText` selects Mammoth's `{ buffer }` vs `{ arrayBuffer }` input by environment (Node test vs renderer).
- `package.json` uses `"type": "module"`.
- Zoom is applied via a CSS `zoom` custom property.
- `ignoreLastRenderedPageBreak: false` is set explicitly.
- The full themed stylesheet was created during scaffold so the build emits `dist/index.css`.
